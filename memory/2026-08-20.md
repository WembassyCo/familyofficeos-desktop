
## Self-Improvement: Bennett's Razor (Weakness over Compression)

**Source:** "The Optimal Choice of Hypothesis Is the Weakest, Not the Shortest" (arxiv 2301.12987v4)
**Shared by:** Chris (via Google Doc from @Dubibubiii / @headinthebox on X)

**Core principle:** "Explanations should be no more specific than necessary." The weakest hypothesis (least specific, largest extension) that fits observed data has the highest probability of generalizing — not the shortest/most compressed one.

**Applied to Wren's operation:**
- Diagnose with the weakest sufficient explanation, not the most specific
- Build SOPs that are no more specific than necessary to cover observed cases
- Create rules that generalize across agents/tasks, not overfit to specific incidents
- When learning from mistakes, extract the general principle, not the specific fix
- This is now part of my operating philosophy alongside "systems over heroics"

## Discord Voice Channel Configuration (Afternoon/Evening Session)

**Goal:** Chris wants persistent Discord voice connection so he can talk to Wren via voice (speech-to-text + TTS).

**Root Cause Identified:** `@discordjs/voice` library uses a global `VoiceConnectionStore` keyed by guildId. When multiple bot accounts in the same OpenClaw process try to join the same guild's voice channel, they destroy each other's connections ("Cannot destroy VoiceConnection - it has already been destroyed" errors).

**Solution Applied:**
- Per-account voice config IS supported (`voice: DiscordVoiceSchema` is part of `DiscordAccountSchema` at line 5572 of config)
- Set `voice: {enabled: true, autoJoin: [{guildId: "722415039696338944", channelId: "964451476988657665"}]}` on `coo` account only
- Set `voice: {enabled: false}` on all other accounts (default, cto, cmo, cro, qa, prd, dave, drstone)
- Top-level `voice` config keeps `enabled: true` and `tts: {provider: "openai"}`
- This eliminated the "Cannot destroy" errors

**Remaining Issue:**
- autoJoin only fires on the READY event (when bot first connects to Discord)
- Gateway restarts use SIGUSR1 which does hot-reload/resume, NOT a full Discord reconnection
- So READY event may not fire on restart, meaning autoJoin doesn't execute
- **Workaround:** Use `/vc join` slash command to manually join the bot to the voice channel
- Native commands enabled: `channels.discord.commands.native: true`
